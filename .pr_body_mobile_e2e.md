## Summary

Live-server E2E suite (`tests/test_mobile_e2e.py`) that mirrors the
Android app's real use cases. Talks to the running stack over HTTP (not
TestClient) so it validates the exact path the phone takes.

### Use cases covered

- **Server reachable** — `GET /health`
- **Login** — register → token; login → token; wrong password → 401;
  token-gated access (401/403); new user gets 3 free credits
- **Tracker** — create from URL (201); duplicate → 409; credit deducted
  3→2; appears in list; refresh endpoint (200 or 429 throttle);
  target-price update (query param, not JSON body)
- **Scraper** — polls `GET /tracked-items/{id}` until the on-demand
  fetch settles (≤180s), then requires a real live price
  (`fetch_status == "ok"` with `lowest_price.price_local > 0`).
  `blocked` / `fetch_failed` / `no_price_found` fail with an actionable
  message (the phone would show a dead tracker).

### Notes

- A unique query suffix per run keeps runs independent: the API's
  duplicate-tracker check is global (any user tracking a URL blocks
  everyone else).
- Not picked up by CI (CI runs `pytest services` only). Needs the stack
  up: `docker compose up -d`, then `pytest tests/test_mobile_e2e.py -v`.
- Env overrides: `API_BASE_URL`, `TEST_PRODUCT_URL` (default: stable
  Compumarts product page), `SCRAPER_TIMEOUT_SEC` (default 180).

### Verification

13/13 pass against the live Postgres stack (real 3400 EGP price fetched
from Compumarts).
