## Summary

Postgres-compat bugs from the reconciled operational schema (INTEGER PKs).
SQLite masked all of them with its lenient typing; the API container
crashed at startup on any fresh PostgreSQL database.

### 1. Subscription/Refund user_id FK types

`users.id` is `OperationalIdType` (INTEGER), but **`Subscription.user_id`**
and **`Refund.user_id`** were declared `String(36)`. `create_all()` fails
with `DatatypeMismatch` ("foreign key constraint cannot be implemented").

- `subscription_models`: `Subscription.user_id` → `OperationalIdType`
- `admin_models`: `Refund.user_id` → `OperationalIdType`
- `routers/subscription`: 6 `str(user.id)` call sites → `user.id`
- `routers/payment`: 8 `record_payment_event(user_id=str(user.id))` →
  `user_id=user.id` (`PaymentAuditLog.target_user_id` is INTEGER)

Redis staging-store string ops (`store.set` / `bound_user` compare) are
intentionally left as strings — Redis values are strings. All other
`users.id` FKs already used `OperationalIdType`; only these two models
were inconsistent.

### 2. Tracked-items id validation

`_validate_item_id` required a UUID on PostgreSQL, but `TrackedItem.id`
is `OperationalIdType` (INTEGER) on both dialects. Every item-scoped
route (detail/refresh/toggle/delete/target-price/stores) rejected the
real id with 422. Validation now accepts numeric strings in both
environments. Also drops the dead `TrackedItemResponse` model
(`id: UUID`, never used — routes return dicts).

### 3. In-flight fetch status

`_aggregate_fetch_status` reported `('ok', None)` when every store is
still in flight (NULL status), so the app could not show its fetching
spinner — a tracker mid-fetch looked like a settled no-price item.
Now `(None, None)` = in flight, `('ok', None)` = at least one store
fetched, matching the app's `TrackedItemModel` contract
(`fetchStatus` null = in flight).

## Verification

- 377 API tests pass (subscription, payments, payment security, credits,
  tracked items, public API)
- ruff + black clean
- API boots against PostgreSQL with all 27 routes registered
- Live Postgres stack passes the 13-test mobile E2E suite
  (register → tracker → live price fetch of 3400 EGP from Compumarts)
