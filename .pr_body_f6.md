## Summary

Implements **Feature 6: Admin & Dispute Management** from `plans/paymob-integration.md`, extending the existing admin endpoints (login, manual payments, contact reveal, approve, reject) with the full admin surface.

## Endpoints (all admin-scoped JWT, plan 6.1)

- **`GET /admin/payments`** — now a **unified view** across all four payment tables (manual / card / wallet / cash), normalized into one list with `status` / `date_from` / `date_to` / `user` filters. Phones masked by default (plan 6.3); full reveal stays on the audited `/admin/payments/{order_ref}/contact` endpoint.
- **`POST /admin/payments/{order_id}/refund`** — processes a refund: claws the package's credits back from the user, records an **idempotent** `Refund` (a second refund for the same order is 409), and logs the action. Refunds are irreversible (plan 6.4).
- **`POST /admin/users/{user_id}/adjust-credits`** — manual credit override with a **required reason**; adjustments whose magnitude exceeds 50 credits require a **second, distinct admin's approval** (`approver_id`) (plan 6.2).
- **`GET /admin/audit-log`** — reads the append-only audit trail with `event_type` / `user_id` / `date_from` filters (plan 6.5).

## Security

- Every mutating action is attributed to the acting admin (id + username + IP) and written to the append-only `PaymentAuditLog` (plan 6.2/6.5).
- New audit actions `refund` and `adjust_credits` added to the `PaymentAuditLog` CHECK constraint (ORM + `infra/sql/schema.sql`) and to `PAYMENT_EVENT_TYPES`.
- New `Refund` model + `refunds` table (idempotency guard against double-deducting credits).
