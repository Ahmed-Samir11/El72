## Summary

Implements **Feature 7: Recurring Subscriptions (v2)** from `plans/paymob-integration.md`. Monthly automatic payments where the user's card is charged every month by Paymob.

## Endpoints

- **`POST /subscription/create`** — creates a subscription (first charge + monthly mandate). Bearer-authenticated; the monthly amount is server-determined from the package (the client never sets it, plan 7.1). Grants the package credits on the first charge. One active subscription per user (409 on duplicate).
- **`POST /subscription/cancel`** — cancels the subscription (owner only, plan 7.1/7.4). Immediate; effective at the end of the current billing period.
- **`GET /subscription/status`** — returns the user's active subscription (`active`, `package`, `next_charge`).

## Billing webhook

- **`POST /webhook/paymob/subscription-renewal`** — fired by Paymob each month when it charges the card. HMAC-verified and idempotent (unique `paymob_renewal_id`, plan 7.6).
  - On **success**: grants the package credits, advances `next_charge` a month, resets the dunning counter.
  - On **failure**: increments the dunning counter; after **3 consecutive failures** the subscription is auto-canceled (plan 7.2).

## Schema

- New `Subscription` + `SubscriptionRenewal` models (`services/api/subscription_models.py`).
- `SubscriptionRenewal` is append-only (DB trigger) with a unique `paymob_renewal_id` idempotency guard.
- New audit actions: `subscription_created`, `subscription_canceled`, `subscription_renewal_succeeded`, `subscription_renewal_failed`, `subscription_auto_canceled` (ORM + `infra/sql/schema.sql` + `PAYMENT_EVENT_TYPES`).
- Migration `infra/sql/migrations/0010_subscriptions.sql` + `schema.sql` parity.

## Security

- Only Paymob tokens cross the wire; card data never reaches us (PCI-DSS requirement 7.1).
- The staging token is atomically consumed (single-use) and bound to the authenticated user.
- Cancellation is owner-only (a different user cannot cancel).
- Every event is written to the append-only `PaymentAuditLog`.
